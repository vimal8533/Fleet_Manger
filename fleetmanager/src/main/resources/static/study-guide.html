🚩 2. Project Genesis: Where It Started

Baseline Setup Before Redesign:

  • Database Table: Single PostgreSQL table robots with columns (id, current_node, battery_percent, status).
  • Hardcoded Movement: RobotMonitorService.java moved all robots continuously through an endless hardcoded array: 
    String[] NODES = {"A", "B", "C", "D", "E"};
int nextIdx = (currentIdx + 1) % NODES.length; // Blind cyclic rotation
  • No Topology: Corridors had no distances, no obstacles, and no track routing.
  • No Missions: Robots had no customer tasks or delivery destinations.

🚀 3. The 5 Evolutionary Phases

Phase 1 Task Management System

Goal: Transform random movement into customer-requested, prioritized missions.

  • JPA Entity: Task.java with fields id (e.g. TSK-ED99D8), pickupNode, destinationNode, priority (1-10), status, and assignedRobotId.
  • State Machine (TaskStatus.java): CREATED ➔ ASSIGNED ➔ RUNNING ➔ COMPLETED / FAILED.
  • REST API: POST /api/tasks (Create mission) and GET /api/tasks (List queue ordered by priority DESC).

Phase 2 Warehouse Graph Topology & Dijkstra Router

Goal: Provide realistic spatial corridors and shortest path route optimization.

  • Graph Model (WarehouseGraph.java):
    • 5 Stations: A (Alpha), B (Beta), C (Gamma), D (Delta), E (Epsilon).
    • Perimeter Single Corridors (Weight = 1): A-B, B-C, C-D, D-E, E-A.
    • Cross-Aisle Diagonal Expressways (Weight = 2): B-D, A-C.
  • Dijkstra Algorithm (RouterService.java):
    • Calculates mathematical shortest path using PriorityQueue<NodeDistance>.
    • Example: Route A ➔ C calculates direct diagonal [A, C] with cost = 2.
  • Interactive SVG Map: Added to index.html with glowing route highlights and station click listeners.

Phase 3 & 4 Dispatcher Engine & Autonomous Navigation

Goal: Match eligible idle robots to missions and guide them step-by-step.

  • Dispatcher Engine (DispatcherService.java):
    • Selects highest priority CREATED tasks.
    • Filters available robots: status == IDLE and battery >= 25%.
    • Prevents double assignment by atomically locking robot to task.
  • Mission Navigation Loop (RobotMonitorService.java):
    1. Robot at Start Node ➔ Navigates Dijkstra route to Pickup Station.
    2. Arrives at Pickup ➔ Task transitions to RUNNING.
    3. Navigates Dijkstra route from Pickup to Destination Station.
    4. Arrives at Destination ➔ Task transitions to COMPLETED.
    5. Robot halts and transitions back to IDLE standby.

Phase 5 Exclusive Resource Scheduling & Deadlock Prevention

Goal: Guarantee zero physical collisions and circular deadlocks on single-lane corridors.

  • Exclusive Station Locks: Only one robot can occupy a station node at a time (tryReserveNode).
  • Canonical Single-Lane Edge Locks: Corridors are shared tracks. To prevent head-on crashes, keys are canonically sorted: 
    String edgeKey = (u.compareTo(v) < 0) ? (u + "-" + v) : (v + "-" + u);
    Robot entering A ➔ B locks "A-B", blocking opposing robot from entering B ➔ A.
  • Deadlock Counter & Detour Bypasses:
    • When blocked, robot yields (status: WAITING) and increments waitCounters.
    • At ≥ 2 wait cycles, RouterService.findShortestPathAvoidingNodes calculates a dynamic detour bypass around the blocked node, breaking circular waits!

💻 4. Command Line Manual (Cheat Sheet)

1. Build and Run Tests

# Run all 18 automated Unit & Integration tests:
cmd.exe /c "mvnw.cmd test"

# Launch Spring Boot in dev server mode:
cmd.exe /c "mvnw.cmd spring-boot:run"

2. REST API cURL Commands

# Dispatch a new task (Pickup at A, Destination at C, Priority 10):
cmd.exe /c "curl.exe -s -X POST -H \"Content-Type: application/json\" -d \"{\"pickupNode\":\"A\",\"destinationNode\":\"C\",\"priority\":10}\" http://localhost:8080/api/tasks"

# View all queued and completed tasks:
cmd.exe /c "curl.exe -s http://localhost:8080/api/tasks"

# Test simultaneous opposing missions (Collision Avoidance Demo):
cmd.exe /c "curl.exe -s -X POST -H \"Content-Type: application/json\" -d \"{\"pickupNode\":\"A\",\"destinationNode\":\"C\",\"priority\":10}\" http://localhost:8080/api/tasks & curl.exe -s -X POST -H \"Content-Type: application/json\" -d \"{\"pickupNode\":\"C\",\"destinationNode\":\"A\",\"priority\":9}\" http://localhost:8080/api/tasks"

# Inspect active node and corridor reservations:
cmd.exe /c "curl.exe -s http://localhost:8080/api/warehouse/reservations"

# Get Dijkstra shortest route between stations:
cmd.exe /c "curl.exe -s \"http://localhost:8080/api/warehouse/route?from=A&to=C\""

3. PostgreSQL Direct Inspection
